# معماری هاست خارج — ربات کامل

## اصل طراحی

```
┌─────────────────────────────────────────────────────────────┐
│  هاست خارج (cPanel + PHP + MySQL)                           │
│  • webhook + ack سریع (fastcgi_finish_request)              │
│  • منو، کاتالوگ، خرید، تخفیف، زرین‌پال → محلی             │
│  • عضویت کانال → getChatMember محلی                         │
└──────────────────────────┬──────────────────────────────────┘
                           │
          ┌────────────────┴────────────────┐
          │                                 │
    کش (push رویدادی)                 delegate/API زنده
          │                                 │
          ▼                                 ▼
   bootstrap, catalog              ثبت‌نام، C2C رسید، SAT،
   messages, flags                 پشتیبانی+رسانه، ادمین، گروه
                                          │
                                          ▼
                              سرور ایران (Laravel کامل)
```

## مسیریابی UpdateRouter

| شرط | مقصد |
|-----|------|
| کاربر تأییدنشده | ثبت‌نام محلی + OTP API |
| ادمین داخل پنل | sync relay به ایران |
| گروه گزارشات (پشتیبانی) | محلی (`HostSupportService`) |
| سایر گروه / chat_member | enqueue به ایران |
| state: C2C receipt, SAT, admin | relay |
| کاربر عادی verified | handlers محلی |

## اصل (آفلاین‌اول)

- **وب‌هوک:** فقط MySQL محلی + تلگرام — **هیچ انتظاری برای ایران نیست.**
- **به‌روزرسانی دیتا:** push فوری از ایران به `host-sync.php` (پرداخت، حساب، کاتالوگ) — **بدون کرون روی هاست**.
- **ثبت‌نام / پرداخت:** در صف `pending_iran_updates` → `BackgroundIranRelay` وقتی ایران در دسترس بود.
- **پشتیبانی:** کاملاً محلی روی هاست (فوروارد به گروه گزارشات + پاسخ ادمین) — بدون ایران.

| لایه | نقش |
|------|-----|
| **MySQL هاست** | کاتالوگ، پیام‌ها، حساب کاربر (snapshot)، منو، map پیام‌های پشتیبانی |
| **Push ایران** | `refresh_catalog` / `push_account` + `notification` (مثلاً بعد از پرداخت) |
| **صف ایران** | relay بعد از هر webhook (`iran_relay_per_webhook`) — **کرون لازم نیست** |

### بدون ایران چه کار می‌کند؟
منو، دوره/سمینار، حساب (از کش)، خانواده/معرفی (از کش)، عضویت کانال (کش API تلگرام)، **پشتیبانی زنده به گروه گزارشات**.

### فقط وقتی ایران وصل است
ثبت‌نام کامل OTP، پرداخت، سات، پنل ادمین، ظرفیت سمینار لحظه‌ای، تخفیف هنگام خرید.

## دادهٔ کاربر (آینه روی هاست خارج)

| محل | چه چیزی |
|-----|---------|
| **MySQL هاست** | `telegram_accounts_cache` — هویت، لیست محصولات خریداری‌شده، متن «حساب من»، خانواده، معرفی، صفحهٔ دسترسی به دوره |
| **سرور ایران** | منبع حقیقت (کاربر سایت، سفارش، دسترسی دوره) |
| **Push** | بعد از ثبت‌نام، ویرایش حساب، **تکمیل سفارش** → `push_account` (+ پیام فوری `notification` برای پرداخت) |
| **Pull** | فقط دستی/اضطراری — `pull_sync_enabled=false` پیش‌فرض |
| **وب‌هوک** | فقط MySQL محلی → تلگرام؛ **هیچ درخواستی به ایران ندارد** (به‌جز delegate ثبت‌نام/پرداخت/پشتیبانی) |

### بدون ایران چه کار می‌کند؟
منو، کاتالوگ، «حساب من»، خانواده، معرفی، نمایش دورهٔ خریداری‌شده (از کش)، عضویت کانال.

### هنوز به ایران نیاز دارد
ثبت‌نام/OTP، پرداخت (زرین‌پال/C2C)، پشتیبانی زنده، سات، ادمین، ظرفیت سمینار لحظه‌ای، تخفیف هنگام خرید.


- `process-update` — delegate کامل
- `checkout/c2c/start` — سفارش + beginWaitingForReceipt روی سرور
- `support/prepare` — sync state پشتیبانی
- `support/try-reply` — ادامه thread پشتیبانی
- `product/present` — نمایش محصول + عکس
- `referral/summary`, `family/summary`, `sat/open`, …

## وضعیت

| بخش | وضعیت |
|-----|--------|
| ثبت‌نام کامل (قوانین، OTP، نام، start_payload) | ✅ delegate |
| منو + خرید + تخفیف + زرین‌پال | ✅ محلی |
| C2C + رسید عکس | ✅ سرور (state مشترک) |
| پشتیبانی متن/رسانه/reply | ✅ محلی (گروه گزارشات) |
| سات / خانواده / معرفی | ✅ کش محلی (+ سات زنده در صورت نیاز) |
| عکس کاتالوگ | ✅ |
| پنل ادمین | ✅ فقط وقتی ایران وصل است |
| bot غیرفعال | ✅ |

## deploy

1. deploy سرور ایران (routes + LiveController)
2. آپلود `telegram/` + migrate DB
3. `php cron/pull-sync.php`
4. ثبت webhook از پنل ادمین
